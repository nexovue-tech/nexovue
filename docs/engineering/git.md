# Git and change-management standard

- Keep unrelated work out of a change; inspect the worktree before modifying files.
- A change record or feature workspace identifies the specification, status, validation, risks, and documentation impact.
- Preserve Git history when relocating documents or code.
- Never use destructive Git operations to discard user work without explicit approval.
- Commit/branch naming is not yet prescribed; repository-owned CI and release policy remain pending decisions.
