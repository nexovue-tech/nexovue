# Change records

A change record is the workspace for work that is not a product feature: bug fixes, refactors, migrations, infrastructure, security, and engineering-system changes. Each lives in `docs/changes/<id>/` and holds at least a `change.md` and a `status.md`, plus `plan.md` and `design.md` when the change is large enough to need them.

Start from the [templates](../templates/README.md). Feature work belongs under [`docs/features/`](../features/README.md) instead.

- [Gate-found defects](gate-found-defects/bug.md) — a worker whose pipeline failed could never exit, a synthetics suite that judged a failing QA check, and test cleanups that filled development ClickHouse's memory with superseded parts.

- [Console review fixes](console-review-fixes/change.md) — what the whole-product review of every screen found: two places the console stated something untrue, a filter that ran off a phone, and the layout, label and copy corrections behind them.
- [One worker again](one-worker-again/change.md) — profiles go back into the worker every other pipeline runs in, carrying both memory budgets; what the split bought, and what giving it up costs, is on the record.
- [Faster gate](faster-gate/change.md) — the pre-push loop measured and shortened from 470s to 182s: a teardown that stopped waiting on ClickHouse, a parallel Python suite, and four e2e workers counted as four callers rather than one.
- [Platform list first](platform-list-first/change.md) — the admin console's first screen was an empty search box; it is now a table of every customer, newest first, that the search narrows.
- [Gate seeds its own window](gate-seeds-its-own-window/change.md) — five live suites rested on telemetry somebody had generated by hand, so the gate went red with the passage of time; it now seeds the window it asserts on, for 12.4 seconds.
- [Commitment is the bill ceiling](commitment-is-the-bill-ceiling/bug.md) — the billing screen charged for every service monitored while the mandate charged the committed count, so the screen and the bank disagreed about one bill.
- [Decisions 2026-09-21](decisions-2026-09-21/change.md) — the eight decisions the console review left open, closed: two by the founder, six on recommendation, and the three code changes they imply.
- [A clock cannot break a tie](a-clock-cannot-break-a-tie/bug.md) — Postgres `now()` is transaction time, so rows written together tie on `created_at` and lists a human reads could reorder themselves between two loads.
- [Seeded from the environment](seeded-from-the-environment/change.md) — a self-hosted install had no way to create its first account without leaving signup open; it now gets one from the environment, read once.
- [Signup closed by default](signup-closed-by-default/change.md) — the switch and the invite flow both already existed; what was missing was the default, so a deployment that set nothing got an open signup page.
- [Catalogue audited](catalogue-audited/change.md) — the roadmap checked against the code after four documents were found stale in a day; two rows contradicted their own notes, and the gate exposed a test waiting for the wrong write.
- [ClickHouse system logs](clickhouse-system-logs/bug.md) — ClickHouse's own logs held 6.7 GiB of a 7.3 GiB store and most of a 4 GiB memory budget, so the gate failed on unrelated suites; they are now bounded, and development drops superseded parts in 30 seconds rather than 480.
- [Rate limit per person](rate-limit-per-person/bug.md) — signed-in reads were counted per network address, so a team in one office shared one person's budget; they are now counted per person, under a per-organization ceiling.
- [Fresh rebuild check defects](fresh-rebuild-check-defects/bug.md) — two tests failed after `just fresh` rebuilt the stack: a 2FA replay test replayed a code it had never actually submitted, and a signup-uniqueness test assumed a platform organization existed that nothing had seeded.
- [Otel demo profiling door](otel-demo-profiling-door/change.md) — the demo's eBPF profiler is wired into `otel-demo.sh` as a fifth door, and the receiver's gRPC server now accepts the gzip compression a Collector-side exporter — unlike every SDK exporter the demo otherwise uses — sends by default.
- [Token count masking false positive](token-count-masking-false-positive/bug.md) — the credential-keys masking rule matched the bare substring "token", so `gen_ai.usage.input_tokens`/`output_tokens` were destroyed at ingest as if they were credentials; found seeding F29's fixtures, fixed with a word-boundary check that still catches `access_token`/`session_token`/`api_token`.
- [Busiest hour streaming RPC trace](busiest-hour-streaming-rpc-trace/bug.md) — a live trace-listing test fails because its first page of 25 most-recent traces is now dominated by a `payment`→`flagd` gRPC stream reconnecting every ten minutes for seven hours; not a product defect, root-caused; the test now pages past it, by the founder's choice.
- [Ingest cannot be knocked over](ingest-cannot-be-knocked-over/bug.md) — readiness group 1: one row ClickHouse refuses stopped every signal for every customer, and the gRPC port read a whole export before checking its key, so keyless requests could exhaust the receiver's memory.
- [Synthetics suite reads a clean hour](synthetics-suite-reads-a-clean-hour/bug.md) — the synthetics live suite required two days with no failed run, so one outage of a check's target failed it for two days after the target came back; it now reads the newest clean hour.
- [Refusals narrowed to the record](refusals-narrowed-to-the-record/change.md) — a refused row in the log, metric or profile pipeline parked every record in its chunk, so one tenant's bad record took other tenants' healthy telemetry with it; only the refused record is parked now.
- [Tests do not need the demo](tests-do-not-need-the-demo/change.md) — three live suites asserted on data only the OpenTelemetry demo produced, so the gate failed whenever the demo was down; `gateseed` now supplies a synthetic check of our own API, two service edges and the database readings.
- [ClickHouse protects itself](clickhouse-protects-itself/change.md) — readiness group 2a: every read bounded in memory, readers connected as a user that can only read, the live tail held to the caller's own projects, the LLM-calls read capped, and the hosted scheduler given the memory dev measured.
- [Redis goes](redis-goes/change.md) — readiness group 2b (ADR-020): sessions, links, locks and the job queue move to Postgres and Celery is replaced; implemented 2026-10-10 — the stack runs on Kafka, ClickHouse, Postgres and object storage alone.
- [Money is right](money-is-right/change.md) — readiness group 3: deleting an organization cancels its payments first, one live checkout, late or id-less webhooks cannot re-grant or drop, test keys refused in production, and a failed payment gets 7 days then free; implemented 2026-10-10.
- [Deletion finishes](deletion-finishes/change.md) — readiness group 4 (ADR-014): owed erasures are retried by a nightly scheduler run that erases every deleted tenant together, one table at a time, and the API loses its ClickHouse writer account; implemented 2026-10-11.
