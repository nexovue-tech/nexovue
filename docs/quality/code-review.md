# Implementation review

Before reporting completion, the implementer reviews the diff against the feature/change record, accepted design, relevant architecture, and applicable engineering standards.

Review includes unintended file changes, authorization/tenant boundaries, errors and retries, secrets/privacy, migration safety, test adequacy, performance-sensitive paths, and operator impact. Verified issues are fixed before handoff; unresolved risks are recorded in status rather than hidden.

For major work, this self-review is followed by the formal code-review lifecycle gate recorded in its status document.
